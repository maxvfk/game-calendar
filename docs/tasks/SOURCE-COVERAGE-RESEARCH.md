# Задание для исследовательского чата: покрытие и источники календаря

Создано 2026-09-22. Репозиторий: maxvfk/game-calendar.
Это готовый prompt для отдельного чата с веб-поиском и GitHub-коннектором.
Рекомендуемый режим пользователя: Sol High. Не запускай дополнительных агентов.
Выполни исследование и сохрани результат, а не только предложи план.

## Объём одного запуска

Исследуй **ровно одну игру**. Пользователь может назвать game ID:
genshin, hsr, wuwa, zzz, endfield.
Если игра не названа, возьми первую ещё не завершённую из этой очереди:
Genshin → HSR → WuWa → ZZZ → Endfield.
Проверь наличие отчёта в docs/research/coverage-<game>.md:
завершённый отчёт не повторяй, незавершённый продолжи по его Remaining.
После одной игры остановись и дай ссылку на результат. Не исследуй сразу все пять.

Цель: дать интегратору доказательства, позволяющие заполнить реальные пробелы
и выбрать пригодный automatic source. Не нужна энциклопедия сайтов.

## Контекст и границы ответственности

Приложение уже опубликовано:
https://maxvfk.github.io/game-calendar/
Feed: https://maxvfk.github.io/game-calendar/data/events.v1.json

JSON/HTML ingest, reviewed channel, дедупликация и сохранение event IDs работают.
NTE Steam, NTEBuild Beyond the Rails и CZN Prydwen уже реализованы.
Prydwen штатно обновился из Actions в run 35770466875, snapshot commit 064d4ce.
NTE/CZN повторно не исследуй; Circle Bounty — известный отдельный конфликт.

Твоя зона записи: только docs/research/coverage-<game>.md.
Не меняй код, adapters, fixtures, snapshots, reviewed JSON, AGENTS.md,
docs/SOURCES.md или чужие отчёты. Не запускай workflows и не меняй настройки.
Не публикуй события автоматически. Интегратор проверит рекомендации отдельно.
Не связывайся с владельцами сайтов.

## Минимальное чтение репозитория

1. Прочитай текущий AGENTS.md; зафиксируй SHA актуального main и UTC-время аудита.
2. Прочитай data/reviewed/README.md и data/reviewed/<game>.json, если он существует.
   Для Endfield отсутствие reviewed-файла нормально: смотри snapshot и feed.
3. Найди только relevant entries в src/ingest/adapters/index.ts и
   snapshots/<sourceId>.meta.json; в feed выбери события/источники только этой игры.
4. docs/SOURCES.md — исторический upstream reference с частично устаревшими
   утверждениями про другие репозитории, Gitea и доступность. Читай только
   относящийся к игре фрагмент при необходимости, не весь файл.
   Наличие adapter или комментария не доказывает successful refresh.
5. Если feed недоступен, сравни с reviewed/snapshot и явно укажи ограничение.
   Не утверждай, что проверил опубликованный календарь.

Начальные источники уже есть в registry: Game8 для всех пяти, Fandom для Genshin,
wiki.gg для Endfield. Используй их как отправную точку, не повторяй общий поиск
с нуля. Старые блокировки не обходи.

## Задача A — аудит текущего покрытия

Рабочий горизонт: текущие события и официально объявленные будущие события
ближайших 30 дней от времени аудита. Global; различия Asia/Europe/America
сохраняй явно. Не смешивай CN/beta и Global.

Охват: character/weapon banners, временные игровые ивенты, login/check-in,
double rewards, циклические challenge modes с конкретным deadline.
Исключи постоянный контент, PV, livestream, розыгрыши в соцсетях.
Веб-ивенты вынеси отдельно как вопрос охвата, если они встретились.

Сверь перечень с официальными version/update/event notices. Для каждого
проверенного события укажи:
- название и существующий event ID, если найден;
- начало/конец буквально как в источнике, включая год, timezone и server;
- точный URL публикации, а не главную страницу;
- результат: covered / missing / conflicting / insufficient evidence;
- рекомендуемое действие и уровень точности даты.

Не придумывай отсутствующие границы, timezone или год; не достраивай cadence.
After maintenance не означает scheduled maintenance end.
Если только даты — day; неизвестный конец — null.
При неизвестном server timezone не конвертируй в UTC.
Разделяй официальную дату, secondary оценку и собственный вывод.
Названия существующих событий не переименовывай: IDs привязаны к localStorage.
Если полный перечень не установлен, прямо напиши, какая часть не проверена.

## Задача B — узкий выбор источника для автоматизации

Начни с текущих источников и официальных notices. Если обнаружен конкретный
пробел, проверь максимум 3 разумных новых кандидата. Остановись, когда найден
один обоснованный основной кандидат и, при необходимости, один fallback.

Для кандидата зафиксируй:
- canonical provenance URL и extraction URL, если они различаются;
- покрываемые категории, актуальность, регион и timezone;
- наблюдаемый формат: HTML, публичный JSON/API, JS-shell, изображение;
- доступность именно в твоём инструменте и дату проверки;
- robots.txt URL, применимые правила/crawl-delay, релевантные условия;
- требуется ли Actions probe, fixture, OCR/manual review;
- риски: отсутствие года, неоднозначный server time, названия-дубликаты.

Search-rendered текст годится для discovery, но не является raw HTML fixture
и не доказывает, что parser сможет прочесть HTTP response.
Без реального Actions run помечай runner availability как UNVERIFIED.
Не ищи private/undocumented API, не обходи robots, CAPTCHA или access controls.
Недоступное правило доступа помечай unknown, а не allowed.
Ссылки и короткие точные выдержки предпочтительнее длинных перепечаток.
По документированному публичному API укажи официальную документацию/условия;
не переноси Steam-specific разрешение на другие API.

## Формат единственного отчёта

Файл: docs/research/coverage-<game>.md, преимущественно по-русски.

1. Status: complete или partial; checkedAt UTC; baseline main SHA;
   регион, горизонт и реально проверенные ресурсы.
2. Краткий вывод: главный пробел и рекомендуемый следующий шаг.
3. Таблица событий: title / existing ID / source boundaries / timezone-region /
   comparison status / publication URL / action.
4. Таблица источников и рекомендации по автоматизации.
5. Integration handoff: приоритетные исправления, 3–5 конкретных
   source-grounded примеров для будущих tests, список нужных Actions probes.
6. Remaining: конкретные неизвестные и критерий их разрешения.
   Отличай «не нашли», «не проверяли» и «источник противоречит другому».

Размер — ориентировочно до 1500 слов плюс таблица событий.
Если доступов не хватает, сохрани полезный partial report вместо бесконечного поиска.

## Сохранение и завершение

Разрешено создать/обновить только свой отчёт отдельным осмысленным commit
research: audit <game> calendar coverage and sources.
Перед записью перечитай актуальный main и свой файл: не перетирай чужие изменения,
не используй force push, не откатывай ветку. Предпочти отдельную ветку
research/<game>-coverage и draft PR в main. Не сливай PR: интегратор его проверит.
Если коннектор не позволяет сохранить, верни полный отчёт в чате и явно скажи
о несохранённом результате. Не утверждай, что создан commit/PR без подтверждения.
Не выдавай research за проверку кода; tests/build здесь не запускались.
В конце дай ссылку на отчёт/PR, SHA commit, 3 основных вывода и Remaining.
